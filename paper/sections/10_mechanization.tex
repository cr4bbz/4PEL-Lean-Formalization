\subsection{Proof style}

The development combines generic theorems with finite executable witnesses. The generic parts include the knowledge/belief factorization, robustness equivalence, Boolean wall-count laws, rational affine crossing, crossing uniqueness, order trichotomy, and midpoint phase classification. Finite constructions are used where an existential semantic possibility is at issue, most notably for stability fracture/restoration and complete dynamic reachability.

Several of the finite cases are discharged by \texttt{native\_decide}. This does not weaken their status: the corresponding propositions are closed finite statements, and Lean’s kernel checks the resulting proof term. The paper nevertheless distinguishes these executable witnesses from general symbolic theorems because their quantifier structure is different.

The affine path development intentionally avoids adding Mathlib. It imports Lean Core rational lemmas and proves the required unit-interval and monotonicity facts directly. This keeps the current result lightweight and makes the boundary to a future topology-heavy development explicit.

\subsection{Status discipline}

The manuscript uses the following hierarchy:
\begin{enumerate}[label=(\arabic*)]
  \item \textbf{Lean-verified theorem}: a universally quantified or closed proposition compiled successfully through the active root import.
  \item \textbf{Finite executable witness}: a concrete model theorem checked by computation inside Lean.
  \item \textbf{Structural interpretation}: a conceptual reading of the formal results, not a separately mechanized theorem.
  \item \textbf{Literature or novelty claim}: a comparative scholarly assertion requiring an external audit.
\end{enumerate}

The central dynamic modules through \texttt{ModalDynamicsIntermediatePhase.lean} have passed a fresh local \texttt{lake build}. Accordingly, the reachability, robustness, wall geometry, affine crossing, crossing-order, and intermediate-phase claims in Sections~\ref{sec:reachability}--\ref{sec:intermediate} are reported as machine-checked.

\paragraph{Reproducibility.}
A minimal reproduction sequence is:
\begin{verbatim}
git fetch origin research/preface-case-study
git checkout research/preface-case-study
git pull --ff-only
lake build
\end{verbatim}
The paper source itself is intentionally separate from the Lean build so that manuscript compilation does not become a prerequisite for checking the formal logic.
